# 🧪 NSFR benchmark prototype

**K-NSFR** · [Overview](../../../README.md) · [Documentation](../../../README.md#documentation) · [Governance](../../../docs/GOVERNANCE.md)

[![Stage](https://img.shields.io/badge/Stage-Prototype_setup-BF8700?style=flat-square)](../../../README.md#status)

This document specifies **what the prototype calculates**: an independent
recalculation of the net stable funding ratio of the EU CRR, used as a
benchmark against a bank's own C 80.00, C 81.00 and C 84.00 figures. It is not
the methodology of record: the regulatory source register (#8), the contracts
(#9) and the fixtures (#10) govern, and the prototype enters them only through
reviewed changes.

> [!WARNING]
> Prototype, not for regulatory reporting. The factors are transcribed from the
> CRR and cross-checked with the standard-factor columns of the reporting
> templates, not yet against registered sources (#8). The VBA has run in
> LibreOffice's VBA compatibility mode only: **no Microsoft Excel run is
> recorded** (#14).

<a id="workflow"></a>

## 🧰 Workflow

1. Run `python tools/build_template.py` (it needs `xlsxwriter`), open
   `templates/NSFR_Template.xlsx`, save it as `.xlsm`, import the seven
   `.bas` modules of `src/core`, `src/api` and `src/host` (Alt+F11,
   File > Import File), save and reopen with macros enabled.
2. **Params**: reporting date, currency, perimeter and the profile
   `eu-crr-standard`. The factor table lists every row of C 80.00 and
   C 81.00 with its regulatory factors (grey) and the applied factors
   (yellow) that the run uses; the category table maps each classification
   code to template rows; the summary map builds C 84.00.
3. **Positions**: one row per position, or none to reconcile the bank's
   figures only.
4. **BankCells**: the bank's figures as (template, row, column, value).
   *Import bank workbook* reads every visible sheet whose title starts with
   `C 80.00`, `C 81.00` or `C 84.00` and that has one header row of column
   codes (`0010`, `0020`...) and one column of row codes, as text, as in the
   templates of Annex XII. *Import bank CSV* reads the export format
   `RowColumn_Index,Suffix,Amount`, for example
   `C 80.00 c0010 r0040,a,123.45`. C 82.00 and C 83.00 are recognised and
   not imported.
5. *Run benchmark* (`RunNSFR`) writes Results, C80, C81, PositionCalc,
   Reconciliation and Checks.

## 🧮 Calculation

```text
stable funding of a cell = amount x applied factor
NSFR                     = ASF (C 81.00, row 2) / RSF (C 80.00, row 1)
```

**Classification.** A position's category gives its template, its bucket
rule and up to three rows, chosen by encumbrance:

| Bucket rule | Bucket |
| --- | --- |
| `MATURITY` | From the maturity date; a blank date takes the category's undated bucket, or is rejected when it has none; `BucketOverride` sets it (for example for options under Art. 428j) |
| `HQLA` | The HQLA column of C 80.00 |
| `FIXED1`, `FIXED3` | `< 6M`, `>= 1Y` (trade date items, CET1, commodities, non-traded equities) |
| `DERIVATIVE` | Netted, see below |

**Residual maturity.** `< 6M` when the date is before the reporting date
plus 6 calendar months, `6M-1Y` when before plus 12 months, otherwise
`>= 1Y`; months are calendar months with the day clamped to the month's end.
A maturity before the reporting date is kept in `< 6M` with a note. The
encumbrance end date selects the row the same way: unencumbered or
encumbered for less than 6 months, 6 months to less than 1 year, 1 year or
more. Encumbrance on a liability is rejected.

**Factors.** The applied factor of the row and bucket, or the position's
`FactorOverride`. An applied factor that differs from the regulatory one,
or an override, makes the run `WHAT-IF`. Rows 1.6, 1.10.1, 1.10.5 and 2.4
have no regulatory factor: their applied factors are those set by the
competent authority, listed as INFO.

**Derivatives** [Art. 428d, 428s(2), 428ah(2), 428k(3)(a)]:

```text
NSFR derivative assets      DA = max(0, positive fair values - variation margin received)
NSFR derivative liabilities DL = max(0, negative fair values - variation margin posted)
row 1.7.1  (5%)   gross negative fair value
row 1.7.2  (100%) DA - DL, when DA > DL
row 2.7    (0%)   DL - DA, when DL > DA
```

Fair values are entered per netting set, already netted, as absolute values.

**Memo rows.** An "of which" row receives the amount of every category that
names it, in the buckets the row has, weighted with the factor of the main
row, and stays out of the totals.

**Aggregation and C 84.00.** Each parent row sums its children, deepest
first. C 84.00 follows the summary map of Params: 2.3 excludes the
operational deposits of 2.3.0.2, 2.4 adds them to 2.5.3.1, 2.6 excludes
2.5.3.1 and 2.9 includes 2.7.

**Status.** `VALID`; `INVALID` when a position is rejected or the RSF is
zero (totals withheld, the bank checks still run); `STOPPED` when the
profile, the reporting date, a Params table or a BankCells setting is
unusable; `NO POSITIONS` when only the bank's figures are reconciled.

<a id="reconciliation"></a>

## ⚖️ Reconciliation

Bank amounts are multiplied by `AmountScale`; factors and the ratio are not.
A template cell without an applicable-factor cell takes 0% in the template's
own formula, and the bank's figures are re-performed the same way.

| Check | Compares |
| --- | --- |
| `ARITHMETIC` | Each row's stable funding with its amounts x applicable factors; each parent's amounts and stable funding with its children's; C 84.00 with the bank's C 80.00 and C 81.00 |
| `FACTOR` | Each applicable factor that carries an amount with the regulatory factor; `SF impact = amount x (regulatory - bank)`; a blank factor on an amount is `MISSING`, also on a memo row whose factor feeds C 84.00 |
| `AMOUNT` | Each amount with the benchmark's (positions run `VALID`) |
| `STABLE FUNDING` | Each row's stable funding with the benchmark's |

A parent without a cell in a bucket carries its children's amounts upwards:
C 80.00 row 1.7 has no HQLA cell, its child 1.7.3 has one.

**Attribution.** Four levels of ASF, RSF and NSFR, and the effects between
them:

```text
reported      the bank's C 84.00, else its C 80.00 / C 81.00 totals
re-performed  bank amounts x bank factors, summed bottom-up
restated      bank amounts x regulatory factors
benchmark     the positions run

arithmetic                 = re-performed - reported
factor effect              = restated - re-performed
amounts and classification = benchmark - restated
```

A worksheet error in the bank's file is imported as `ERROR` and reported as
not a number. When the bank's C 84.00 NSFR is unusable, the reported level
takes its C 80.00 / C 81.00 totals, with a warning.

**Known template gap.** C 81.00 has no 6M-1Y factor cell for AT1, Tier 2 and
other capital instruments (rows 0040-0060); the CRR gives 50% [Art. 428l(d);
EBA Q&A 2021_6017]. The benchmark applies 50%, and the FACTOR check names the
cell when the bank reports an amount there.

## ✅ Verification

| Evidence | Result |
| --- | --- |
| Regulatory factors against the standard-factor columns of the C 80.00 / C 81.00 templates | 230 cells compared, 5 differ: rows 2.1.2-2.1.4 at 6M-1Y (template gap above) and two cells of row 2.7 without an amount cell |
| `nsfr_reference.py`, independent of the VBA, on the synthetic demo | Expected values in `demo.expected.json` |
| `tools/lo_regression.py`: the VBA in LibreOffice 24.2, on the generated template | Demo: 340 of 340 TestCatalogue rows PASS; invalid position: totals withheld; CSV import: same headline; injected bank defect: `FACTOR MISSING`, ERROR and WARNING; error value imported as `ERROR` |
| Microsoft Excel (Windows, 64-bit) | **NOT RUN** (#14) |

The demo bank figures are the benchmark's results with five documented
differences (classification, factor, arithmetic, amount and the template
gap), so that every check and every effect of the attribution is exercised.
LibreOffice reads a worksheet error as 0 through its VBA layer, whereas Excel
returns an error value; the error path is therefore tested on the import
procedure directly.

<a id="limitations"></a>

## 🎯 Limitations

Out of scope: the simplified NSFR (C 82.00 / C 83.00), consolidation,
currency conversion and the per-currency NSFR, national discretions, the
look-through of interdependent items (the factors of Art. 428f are applied
as declared by the category), the derivation of encumbrance from collateral
flows, and the netting of derivatives per netting set (fair values are
entered already netted). The reporting currency and perimeter are informative.
Synthetic data only are committed ([data policy](../../../docs/DATA_POLICY.md)).
